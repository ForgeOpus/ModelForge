# Playground inference

The authenticated `POST /api/playground/infer` endpoint accepts a run ID, an optional registered checkpoint path, a context window (`1024`, `4096`, `8016`, or `32768`), and alternating user/assistant messages ending with a user message. `max_new_tokens` defaults to 256. It returns a reply or token labels. The selected window is capped by the model's known limit; input plus reserved output tokens must fit. ModelForge rejects an oversized conversation instead of dropping earlier messages.

The browser keeps conversation text in component memory. Starting a new chat, choosing another model, or leaving the page discards it. Markdown export is initiated by the user. The server does not persist conversations or keep the model loaded between requests.

ModelForge uses Accelerate to plan a device map within explicit memory budgets. When training is idle, the plan can distribute weights across available CUDA GPUs and CPU RAM, with disk offload if they do not fit. While training is active, the plan excludes GPUs to protect the trainer's VRAM, but can distribute weights between CPU RAM and disk. It leaves additional RAM for the OS, runtime buffers, and possible training growth. Estimates include the context, attention, cache, and adapter overhead. If a model cannot execute with the available memory, or the offload drive lacks space, the request is rejected.

Offloaded weights are kept in a temporary directory and removed after inference, including on errors. Set `MODELFORGE_OFFLOAD_DIR` to an existing directory to choose the drive; otherwise the system temporary directory is used. Disk offload can be substantially slower than RAM or GPU inference. Model weights are loaded in float32; this path does not quantize them.

These budgets are estimates, not hard reservations: the operating system, training job, or another process can allocate memory after the check. CPU inference can also slow a CPU-bound training run, and GPU inference can share a GPU with other applications. The gate applies to one ModelForge server process; multiple server processes do not share it. For strict isolation or a guarantee against future RAM pressure, run inference after training or implement operating-system resource isolation and cross-process coordination. Models requiring custom remote code are not loaded by this endpoint.
