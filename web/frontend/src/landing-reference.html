How it decides

Four steps between "I have a GPU" and a running job.

Most fine-tuning tools hand you a config file. ModelForge hands you the config and the reasoning behind it, so you can trust it or change it.

01

Detect the hardware

Every visible GPU and its VRAM, plus RAM, CPU cores and free disk. Apple Silicon and CPU-only machines get their own limits.

02

Resolve the task

Your use case and objective map to a model task and a trainer. Instruction following with a supervised objective becomes causal_language_modeling trained with sft.

03

Budget the parameters

For each PEFT tier it computes the largest model that fits, then picks the highest-fidelity tier. Try it on the right.

04

Plan and launch

Candidate models come from the Hugging Face Hub, filtered by task and size. Multi-GPU runs get data-parallel or FSDP. Then training streams live to the console.

Three ways in

Same engine in the browser, the terminal, or a notebook.

Browser console

Configure, launch and monitor runs with the plan explained beside every field.

$ modelforge run

Terminal

An interactive wizard, plus commands to get recommendations or review history without training.

$ modelforge recommend
$ modelforge history

Notebook

Drive the same recommend-and-train workflow from inside a Jupyter notebook.

$ modelforge-nb
